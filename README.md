# 定时群友清理

从 QQ群管插件（`astrbot_plugin_qqadmin`）的「清理群友」逻辑独立出来的定时版本：
定时扫描**不活跃 且 低等级**的群友，先发清理预告，提醒到期后自动踢出。

> 安全提示：这是踢人插件。请先用 `dry_run` 演习模式验证规则，
> 并确认群白名单后再打开自动执行。

## 工作流程

1. 定时器按配置扫描生效群（默认每 7 天一次，可改每日固定时间）。
2. 扫描只认**白名单里的群**（`run_in_all_groups` 默认关闭），并且
   **Bot 必须是该群群主/管理员**，否则跳过该群。
3. 发现候选后先发**清理预告并 @ 名单里的人**（不打扰群主/管理员），
   `remind_before_hours`（默认 24 小时）到期后**按预告名单直接执行，
   等待期间发言不改变结果**；`remind_enabled` 关闭则扫描到就直接执行。
4. 预告等待期内，群主/管理员回复 `确认清理` 立即执行，
   回复 `取消清理` 中止本次任务。
5. 执行后发送成功/失败明细报告；踢人失败不重试、不留尾巴。

候选规则（与 QQ群管一致并加强保护）：

- `最后发言 < 现在 - inactive_days` **且** `等级 < under_level`
- 永远保护：群主、管理员、Bot 自身
- 额外保护：`protected_user_ids` 名单、入群不满 `protect_recent_join_days` 天的新人
- 每次执行只认提醒时的名单（等待期间发言不改变结果）；已离群的跳过，新升为管理的豁免

## 命令（群内，默认群主/管理员可用）

- `/定时清理`：帮助 + 当前状态
- `/清理预览 [天数] [等级]`：只扫描并预览，不踢人；生成待处理任务，
  `manual_confirm_minutes`（默认 10 分钟）内回复 `确认清理` 执行，
  超时自动作废（手动任务**不会**自动执行）
- `/清理执行 [群号]`：立即执行当前待处理任务（默认当前群）
- `/清理取消 [群号]`：中止当前待处理任务（默认当前群）
- `/清理状态`：配置摘要、待处理任务、最近运行记录

AstrBot 超级管理员（`admins_id`）在任何群都可操作。

## 关键配置项

| 配置 | 说明 |
|---|---|
| `enabled` | 定时总开关 |
| `run_in_all_groups` | 对所有群生效（默认关，极高风险） |
| `group_whitelist` / `group_blacklist` | 生效群白名单 / 永不清理的黑名单 |
| `require_bot_admin` | Bot 必须有管理及以上权限（默认开） |
| `inactive_days` / `under_level` | 默认阈值，`under_level` 含"且"关系 |
| `protect_recent_join_days` | 新人群友保护天数，0 关闭 |
| `protected_user_ids` | 永不清理的 QQ 号 |
| `auto_execute` | 定时任务到期是否自动执行（默认开） |
| `remind_before_hours` | 提醒提前量；设为 0 则扫描后直接执行（危险） |
| `manual_confirm_minutes` | 手动预览的确认窗口 |
| `max_kick_per_run` | 单轮踢人上限，多的留到下一轮 |
| `dry_run` | 演习模式，只发报告不踢人 |
| `group_overrides` | 某个群单独用不同天数/等级/开关 |

改定时、阈值等配置后请在插件管理页**重载本插件**使新调度生效。

## 与 QQ群管插件的关系

- 两者的确认关键词都是默认 `确认清理` / `取消清理`：如果同时用 QQ群管的 `/清理群友`，
  回复确认词可能被两个插件同时消费。建议只用一边的清理流程。
- 待处理任务和运行记录存在插件数据目录 `state.json`，重启后仍有效（过期任务自动作废）。
